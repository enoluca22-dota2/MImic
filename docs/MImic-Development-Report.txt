B. ARCHITECTURE
---------------
UI: Compose, single activity (MainActivity, FragmentActivity for the Cast picker), navigation in
  ui/MimicApp.kt (NavHost) + ui/navigation/TopLevelNavigation (tabs Home / Search / Library /
  Radio / Downloads / Settings). Sub-screens are wrapped in InsetScreen for system insets.
State: player/PlayerViewModel.kt (one AndroidViewModel) holds library flows, playback state,
  downloads, online search, account actions. AppContainer (MimicApplication.kt) builds
  repositories lazily.
Playback: player/PlaybackService.kt — ONE Media3 MediaSessionService + ExoPlayer for every source.
  Data source = OnlineMusic.wrap(DefaultDataSource): URIs content:// (phone), file:// (downloads),
  http(s):// (Navidrome, radio) go to Media3's DefaultDataSource unchanged; mimic-yt://track?v=ID
  (online) is resolved at open time by BitChord's StreamResolver and read in 2 MB ranges
  (ChunkedDataSource). MediaSession gives notification, lock screen, Bluetooth/headset keys, audio
  focus, becoming-noisy pause. The service records play history and persists the queue
  (PlaybackStateStore: ids/index/position only). PlaybackEffects: speed/pitch, skip silence,
  crossfade, ReplayGain, EQ, sleep timer.
Library: data/UnifiedLibrary.merge(local, server, downloads, onlineSaved) is the single source of
  truth (PlayerViewModel.songs). Song identity: phone = MediaStore id; Navidrome = hash of server
  id with bit 32 set; legacy cloud downloads = 62-bit in [2^61,2^62); online YouTube = 62-bit
  SHA-256 of "yt:<videoId>" in [2^62,2^63); radio = negative. A download shares its source's id.
  PlayerViewModel.knownSongs = songs + online tracks only played (history / queue restore).
Database: data/db/MimicDatabase.kt, Room v9 (v9 adds `lyrics`). Tables: favorites, play_history, playlists,
  playlist_songs, custom_themes, downloads, favorite_groups, pending_server_ops (stars),
  cloud_accounts/cloud_items (legacy, unused), radio_stations, online_tracks (v8). Migrations are
  additive and listed in MimicDatabase.ALL_MIGRATIONS (androidTest covers v4 → v8).
Navidrome/OpenSubsonic: data/server/ (SubsonicClient salted-token auth with one salt per session,
  ServerCredentialsRepository with the password AES-GCM encrypted by an Android Keystore key).
  Remote access over Tailscale = just the server address (docs/REMOTE_ACCESS.md).
Online music (full edition): app/src/full/java/com/example/mimic/online/ — see section D.
Downloads: Navidrome → data/DownloadRepository.download (in-app, foreground of the VM);
  online → OnlineDownloadWorker (WorkManager foreground dataSync) → DownloadRepository.recordOnline;
  links (YouTube/TikTok URLs) → full-edition downloader/ (yt-dlp, own DB mimic_downloader.db,
  DownloadService). All finished files live in app storage (filesDir/downloads, …/online).
Lyrics (4.5): data/lyrics/ — LyricsRepository.resolve: user .lrc (filesDir/lyrics/<id>.lrc) →
  saved row (Room table `lyrics`, v9) → embedded tags (AudioTags) → sidecar <name>.lrc → Navidrome
  (SubsonicClient.lyrics: getLyricsBySongId, then getLyrics) → LRCLIB (data/audio/LrcLib: /api/get,
  /api/search, free-text search; 3 attempts on 5xx/429/IO; 350 ms pacing). LyricsQuery cleans
  titles/artists (VEVO/Topic/"Artist - Title"/packaging/feat.) and extracts version markers;
  LyricsMatcher only accepts equal cleaned titles, same version markers, credited artist, length
  within 3.5 s (2 s without artist) → Found / Ambiguous (user chooses) / None. Status per song:
  SYNCED, PLAIN, UNAVAILABLE (recheck after 14 days), FAILED (retry after 2 min), NEEDS_CHOICE,
  PENDING. trackKey guard: a row is ignored if the song's cleaned title/artist changed.
  LyricsWorker (WorkManager): one song after a download; Find Missing Lyrics scan (resumable).
  VM.lyrics flow is Eager (lookup starts when a song plays). UI: ui/player/LyricsScreen.kt
  (full screen; shared LyricsContent also used by the Dynamic player), MissingLyricsScreen.kt.
Listen Together (4.5): see section D2.
Accounts: data/account/MimicAccount.kt (Credential Manager "Sign in with Google" → Firebase Auth,
  Firebase initialised from BuildConfig fields read from gitignored firebase.properties) and
  data/account/AccountSync.kt (Firestore users/{uid}/devices/{deviceId} snapshots built with the
  4.3 backup codec; additive merge via SongMatcher + RestorePlanner). YouTube Music connection is
  separate: online/YouTubeMusicAccount.kt (BitChord WebView login on accounts.google.com, cookie
  stored by AuthStore in encrypted prefs). UI: ui/settings/AccountsScreen.kt.
Radio: data/radio/ (bundled stations + Radio Browser directory, countries list default Albania,
  +/− add/remove, DataStore radio_prefs), ui/radio/.
Themes: Theme Studio (14 presets + custom themes JSON v2, glass styles), Player Layout Studio
  (Classic / Immersive / Compact / Dynamic), Home & navigation customisation, Album-Adaptive colours.
Updater: update/ (UpdateManager, UpdateCheckWorker): reads GitHub Releases of the public repo,
  picks the APK for the phone's CPU, verifies SHA-256 (SHA256SUMS.txt), package, version and the
  pinned signing certificate, then hands it to Android's installer (user confirms).
Cast: cast/ (Media3 CastPlayer + LanMediaServer token relay). Backup: data/backup/ (JSON file).
Diagnostics: Settings → Advanced → Download Diagnostics (full): link-analysis attempts and, since
  4.4, an "Online music" section (OnlineDiagnostics: categories + sanitized messages + redacted
  resolver log). Shared as TXT through the share sheet.

D2. LISTEN TOGETHER (4.5)
-------------------------
Server: server/party — BitChord's Go backend (GPL-3.0, header in every file), module mimic/party,
  + host "endParty" (bye reason "ended", party dropped) and "voteSkip" (majority of connected
  devices; votes reset per track; allowed in host-only parties). In-memory only, no database, no
  secrets. Docker: `docker compose -f server/party/docker-compose.yml up -d --build` (container
  mimic-party, port 8000; separate from Navidrome). Tests: `docker run --rm -v <dir>:/src -w /src
  golang:1.27-alpine go test ./...` (all pass, incl. mimic_test.go).
Protocol: REST create/join/preview/leave/snapshot + WebSocket /ws/parties/{code} with the party
  token in the Authorization header (never in URLs, never logged). State = position P at server
  time A + seq; queue travels separately with its own seq; heartbeat every 5 s; 45 s grace for a
  dropped socket; codes 6 characters.
Client: party/ListenTogether.kt (OkHttp, org.json; both editions): server address (no default;
  user enters it), identity = MImic Google account name/photo if signed in, else a nickname (no
  extra account), userId = SHA-256 hash; membership saved in app-private prefs and restored after
  a process restart (GET snapshot; 401/404 → cleared); reconnect loop with jittered backoff;
  ServerClock (best round trip of a ping burst, monotonic clock).
Player binding: player/PartySync.kt in PlaybackService (outlives the UI); the MediaSession player
  is PartyPlayer (ForwardingPlayer) so every user command (app, notification, lock screen,
  Bluetooth) is published; corrections go straight to ExoPlayer. Resumes wait for the server's
  scheduled start; control alignment ±120 ms; drift correction only above 1.2 s on two readings,
  then 6 s cooldown. Focus loss (call / other app) detaches only that phone. Next/previous use the
  server's queue; auto-advance proposes the party's next track (idempotent). The user's own queue
  is stashed on entering and restored (paused) on leaving; queue persistence is paused in a party.
Track identity: party/PartyTracks.kt — online song = YouTube id (+ public https artwork only);
  anything else = "m:" + hash(cleaned title|artist) + length. Each phone resolves to ITS OWN
  source: own download / phone file / Navidrome (library match: same cleaned title, versions,
  credited artist, length ±4 s; offline copies preferred) → own online stream (full edition) →
  "Not available on this phone" (sits the song out). No audio, stream URLs or Navidrome URLs/tokens
  are ever sent.
UI: ui/party/ListenTogetherScreen.kt (Settings → Listen Together): name card, server card
  (Check & save), Start a Party, Join (code or link, preview first), party header (code, avatars,
  host star, connection/latency/sync chip), now playing (source on this phone, controls,
  progress, vote to skip), shared queue (add songs from the library, remove, tap to play), host
  settings (host-only control), listeners (remove), recent activity, Leave / End party.
Invites: mimic://party/CODE?server=URL (manifest intent filter) and http(s)://<server>/invite/CODE
  (server landing page with "Join the party in MImic"). Docs: docs/LISTEN_TOGETHER.md (LAN,
  Tailscale, optional Tailscale Funnel — not enabled by Claude).
