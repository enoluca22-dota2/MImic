## 4. yt-dlp self-update (unsigned)

How it works today: at most once a day, only online and idle, `YtDlpUpdater` calls
youtubedl-android `updateYoutubeDL`, which reads `api.github.com/repos/yt-dlp/yt-dlp/releases`
and downloads the release asset with `FileUtils.copyURLToFile` over HTTPS (system CAs; HTTP to
GitHub is impossible since beta.4). After the swap MImic smoke-tests `--version` and restores the
bundled copy if it fails. There is **no checksum or signature check**, so the trust rests on
GitHub + TLS + the yt-dlp maintainers' account.

Risk: Medium (code that runs inside MImic's sandbox when downloading; it cannot read other apps'
data, but it can read MImic's own files, including downloads and session stores).

Recommended remedies, in order:
1. **Verify yt-dlp's signed checksums (recommended).** Download `SHA2-256SUMS` and
   `SHA2-256SUMS.sig` from the same release, verify the signature with yt-dlp's public release key
   **embedded in MImic** (an independent trust anchor, unlike a checksum file stored next to the
   binary), then check the binary's SHA-256 before installing it. Needs an OpenPGP verifier
   (e.g. Bouncy Castle `bcpg`, MIT-licensed) — list it in THIRD_PARTY_NOTICES.md.
2. Interim, no new dependency: make the automatic update **opt-in** (Settings → Downloads →
   "Update the downloader automatically", default off for new installs, plus "Update now"), so
   updates happen only when you choose.
3. Not recommended: disabling updates entirely (YouTube changes break old yt-dlp within weeks).

## 5. The WebView change already on `main` (540b10d)

`PoTokenWebView`: `allowFileAccess = false`, `allowContentAccess = false`. Its page is loaded with
`loadDataWithBaseURL("https://www.youtube.com", …)` and network loads are blocked, so neither
setting is needed. Verified: compiles; CI (full + standard unit tests, lint), Security and CodeQL
pass on `540b10d`; CodeQL alert #10 closed as fixed; a signed release build of `main` installed on
the emulator streamed an online song without errors. Not verified: the PoToken WebView itself was
not started during that playback (the stream resolved without it), so its BotGuard run with the
new settings has not been observed on a device. Ships with the next release.
